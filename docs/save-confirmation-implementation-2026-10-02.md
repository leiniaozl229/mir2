# 第九批：角色保存、缓存与会话顺序

本批为角色小退、换角色和断线恢复补存档基础。当前生产源码已修复并在隔离入口验证；本机运行服务尚未部署这些保存改动。F12 菜单和游戏→选角连接生命周期仍列为后续实施项。总台账保留 195 项、5 implemented / 180 partial / 10 missing / 0 verified。

## 消息与保存结果

实际参考 `DBServer/DBSMain.pas` 的保存成功为 **1102/Recog=1**，失败为 **1100/Recog=0**；`M2Server/RunDB.pas` 只接受前者。参考 Common 中另一套常量不能混用。当前 DBSrv 使用真实 MemoryPack、EDCode 和签名帧，所有有效保存请求都按原 queryId 返回对应结果。CM1009 和游戏连接关闭没有数据库提交确认语义。

`DataService` 在存储 Update 返回 true 后才发布缓存和释放对应 account/sessionId 的加载状态。false、异常、Add 失败和“Add true 但无索引”返回失败。缓存写入/删除失败时保留绕过标志，随后加载从持久后端读取；缓存清理失败不会把已确认的提交改为未提交。false 或异常也可能发生在 COMMIT 之后，旧缓存因此必须失效，不能据负回执推断数据库没有写入。

缓存首次 Add 现在会实际插入，以不区分大小写的角色键替换已有项。加载仅凭本次取得的加载权进入，重复请求不能通过 foundSession 绕开。缺角色、存储异常、true-with-null 和损坏缓存均有明确失败或持久读取路径；失败请求只释放自己取得的账号/会话状态。

## 并发与连接

原 native 包处理器复用静态可变 RequestInfo，不同 TCP 连接可能覆盖头和正文；现在每包创建独立对象。

独立双 TCP 场景实际复现了三种错序，旧失败日志完整保留：

1. 较早保存已提交但延迟返回，较晚保存先发布缓存，较早请求随后覆盖成旧快照。
2. 同角色的新加载在旧保存返回前取得状态，被保存清理误释放。
3. 同账号/会话换到另一角色时，旧角色保存同样可以释放新角色的加载状态。

最终顺序为 **account → character → 短缓存锁或会话锁**。账号采用与 ClientSession 一致的 Ordinal 比较，角色采用 OrdinalIgnoreCase。存储、缓存发布和精确会话清理处于同一有序操作内；加载的权威取得与失败释放也在里面。门外只读状态查询可以立即拒绝已加载的重复请求，返回 false 后仍需在门内真正取得。独立账号和角色可在另一角色提交受阻时继续保存，已有角色加载者的重复请求可及时拒绝。

ClientSession 的增删、查询、取得、释放、在线状态和 Stop 共用锁，锁内不做 TCP I/O。128 轮竞争和 512 轮会话生命周期调用通过；Stop 清空列表，避免遗留 null 元素。操作字典按进程保留；Monitor 不承诺严格调度公平性。这些检查覆盖已在途保存的排序，没有为 native 协议新增跨进程 nonce，也不能鉴别在后续加载之后才到达的旧会话保存。

## 队列、快照与重连

保存等待按 queryId 关联实际队列项，只接受该项的 1102/1 完成；1100/0 是显式失败，未知和迟到旧 queryId 不清另一项。一个角色的后续快照不能越过其最早的失败或未知结果，其他角色可推进。每次入队重置 RcdSaved，只有自身待保存项全部完成才恢复 true。

入队时用实际序列化往返冻结状态数组、奖励能力、任务和物品附加属性，避免等待期间对象继续变动污染重试。明确负回执可按限额重试同一快照；发送失败保持未发送项，DB 断开保留队列。5 秒无回执是结果未知，继续保留屏障，不自动重发。半包不跨连接代际拼接；实际接收长度、合并帧、断线重连与 Stop 后停止自动连接均已实测。

## MySQL 事务与行完整性

九个子保存方法的异常向外传播，比较物品栏位所需的读取也在同一事务内严格失败。Add 和 Save 只有 COMMIT 正常返回才成功；提交异常不更新快速索引。正常未变化的 UPDATE 可以返回零变化，不能因此拒绝有效存档。

保存前按固定顺序锁定主记录、基础能力与状态记录，核对角色键、记录 ID、账号、删除标记和必需子行，防止不存在的记录被当作“零变化成功”。旧 Add 没有创建奖励能力行，保存用参数化 UPSERT 补齐该行，同时保留现有字段语义。

三类物品表只有 Id 主键，没有 (PlayerId,Position) 唯一索引。现在先读取栏位及 ID，再按已知主键锁定并核对最新的全部物品字段；更新限定 ID、归属和位置。缺失的非空栏位完整 INSERT，附加属性在同事务保存；空缺位可以保持稀疏。重复位置、越界位置、锁前消失或换归属均失败。主角色锁串行化本实现的同角色保存。实际测试在一个角色持有已知物品 Id 行锁期间，另一角色保存仍可完成；其他写入路径的阻塞或死锁、外部写入者绕开该协议的行为仍待核。

隔离 MySQL 检查只从生产库读取十张表的 SHOW CREATE 定义，在本进程独占的随机 schema 内创建新角色、触发器和故障条件。成功、无变化、缺行修复、逐阶段回滚、完整物品/属性、并发锁、重试不重复与 **COMMIT 后抛异常但数据已经写入**均从新连接核对。最后 schema 已删除且确认不存在，没有读取或修改生产账号与角色行。本轮 SQL 未注入网络中断、进程崩溃/重启或丢失 COMMIT 回应；提交后异常为执行入口故障注入，不替代这些运行验收。
