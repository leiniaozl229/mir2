# 金币丢弃与数量协议边界（2026-10-02）

本批补上金币数量协议，UI-034 仍为 `partial`。2026-10-07 已依据仓库原客户端纠正入口、投放位置和弹窗；早期“点击金币数字、放到背包空格”的实现与原端不一致，不再使用。堆叠、拆分及物品部分交易仍不显示为已支持。

## 来源与协议

- Delphi 参考客户端 `FState.pas` 的 `DGoldClick` 把金币作为临时移动项；`DBackgroundBackgroundClick` 是地图背景，先清除移动态，再显示水平 `DMessageDlg`，从 `EdDlgEdit` 读取数量并调用 `SendDropGold`。原文把它误读为背包背景，现已纠正。`DItemGridGridSelect` 对携带金币直接返回。参考版本不能单独证明国服像素和热区。
- 2026-10-07 仓库原端截图52～63及 `gold-world-actions.json` 实测：单击金币图标后单击地图才弹出“你想放下多少金币?”；点击背包空格不会弹窗，也不取消金币，随后地图点击仍能弹窗。数量框只有确定按钮，Escape 保持打开，输入0后Enter关闭且金币仍为17,863。当前没有提交正数丢弃。静态图标为Prguse#29，背包(10,190)、36×21；中心点击已验证，边缘热区、按下态和携带图仍待核对。
- 参考 `ClMain.pas` 的 `SendDropGold` 使用 `CM_DROPGOLD=1016` 和数量参数；固定服务端 `PlayObject.Message.cs` 只接收正参数并调用金币掉落。`PlayObject.Operate.cs` 再校验安全区开关、金币掉落门槛、地图 `NoThrowItem`、角色掉落权限和余额；角色至少保留 1 枚金币。创建地面金币失败会加回余额。网页与网关均不代替这些服务端检查。
- 网关旧协议发送头的 `Param` 是 `ushort`，所以 Web 命令只接受 `1..65535`，投射为 `CM_DROPGOLD.Param`。浏览器还使用最近收到的金币值限制输入不超过 `金币-1`，此限制仅为交互提示；服务端仍用执行时余额验证。
- 普通 `dropItem` 只接受服务端确认的实例号和名字，不带数量字段；参考 `SendDropItem` 的 `Param=0`。当前没有证据允许网页拆出部分装备/物品，所以没有新增拆分控件，也不按可选数量字段伪造服务端数量。

## 网页行为

背包金币图标现在是入口，金额是只读输出。携带金币时，背包格子的点击不拿起物品、不打开输入；地图主键按下拦截移动，抬起后打开数量框。再次点击图标可取消；浏览器Escape取消携带仍是额外恢复入口，不能视为已核对原端行为。生产页和校准页使用同一个GoldDropController与SystemDialogController，校准提交明确作为离线夹具反馈，不修改余额。

金币输入通过system-dialog.json的gold profile绘制：水平Prguse#360、452×179，输入区相对窗口(35,69)、382×22、黑底白字，仅确定按钮。字体取当前mir.ini的楷体配置，字形栅格和基线仍待像素比较。普通名字等输入保留独立配置。共享弹窗在拦截游戏快捷键的同时允许输入框的数字、退格、光标与复制粘贴默认行为；原先所有按键preventDefault会阻止真实键入。

交互代次隔离关窗、断线、失焦或销毁后的旧答案，余额不乐观扣除。pointercancel只处理中断相关输入表面；系统弹窗内部用于停止自身拖动的合成事件不再错误地作废刚打开的金币请求。

发送金币命令后不乐观扣减余额。较小且恰好匹配提交金额的权威 `currency` 更新会显示成功；服务器系统消息、写入拒绝、相同余额更新或等待超时都清除待决状态，不伪造扣款或掉落确认，界面仍显示最后一次服务器金币值。协议没有带请求 ID 的独立掉金币 ACK，因此并发经济更新时只报告待核对状态。
