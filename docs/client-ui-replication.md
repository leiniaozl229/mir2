# 客户端 UI 复刻依据

当前复刻把视觉、交互和服务端状态分开取证，避免再次混用不同客户端版本的坐标。

## 证据来源

| 来源 | 可确认内容 | 当前用途 |
| --- | --- | --- |
| 2003 国服安装包的 WIL/WIX | 窗口底图、按钮帧、图标、透明边界、格线和像素坐标 | 视觉与热区的首要依据 |
| Crystal 客户端源码 | 单击、双击、右键、拖动、窗口移动、状态切换和协议调用顺序 | 国服可执行程序缺少源码时的行为参考 |
| OpenMir2 服务端与实际协议 | 物品实例、属性、金币、装备、使用结果和持久化状态 | 游戏结果的权威来源 |
| 真实浏览器试玩 | 缩放后的命中区域、遮挡、文字基线和完整操作闭环 | 每项功能的最终验收 |

安装包素材可以稳定解析 UI 的外观和像素结构。编译后的客户端程序还能通过静态分析继续找窗口类、消息号、字符串和状态分支，但恢复出的代码可读性有限。仓库中已下载的 Crystal 源码提供了更直接的交互证据：`InventoryDialog` 设置 `Movable = true`，`MirItemCell` 的左键路径调用 `MoveItem()`，双击和右键路径调用 `UseItem()`。它的窗口底图与 2003 国服版本不同，因此坐标不能直接复用。

## 背包契约

2003 国服 `Prguse#3` 的背包窗口是 336×270。实测格线起点为 `(18,14)`，横向步进 36，纵向步进 32，共 8×5 个可见格子。金币文本位于 `(65,190)`、宽 136。坐标与交互已写入 `content/classic-176/ui-layout.json`，前端和校准工具应共同读取或验证这份契约。

背包操作遵循以下顺序：

1. 鼠标悬停显示服务端物品属性，包括持久、等级要求、攻防魔道、附加属性和价格。
2. 左键单击拿起物品，再单击空格完成移动；单击已有物品的格子时交换位置。
3. 双击使用药品或穿戴装备，右键保留同样的快捷操作。
4. 背包排序按角色保存在浏览器本地，物品实例和使用结果仍由服务端确认。
5. 角色、背包、通用窗口及 NPC/商店/修理/仓库窗口可拖动，位置保存在浏览器本地并限制在 800×600 游戏区域内。

## 后续窗口复刻流程

每个窗口先锁定安装包中的底图帧，再通过透明边界和格线检测生成坐标表。随后对照客户端源码或可执行程序静态分析补充点击语义与状态机，最后在现有浏览器里完成打开、悬停、点击、拖动、关闭和重登恢复检查。自动化测试需同时校验设计坐标和服务端操作结果，截图只用于视觉复核。
