# 第十五批：原服删除回执与存储校验

范围为角色删除的原服确认路径。上批网页、网关、原图和测试网关能力保持现状；本批修改原服源码及 MySQL 存储，未部署到运行中的 DBSrv。完整复刻目标继续开放。

## 修复的行为

UserService.DeleteChr 原先把 Get 的“找到了记录”直接复用为“删除成功”：账号不匹配、达到 DeleteMinLevel 时可能发送 SM523，却没有删除。等级查询缺索引、失败时返回 0；MySQL GetQryChar 还可能在没有记录时返回 true。更新索引的 SQL 不检查命中行数，并把 Header.Deleted 写回 false。

现在查找结果和删除结果分开。空账号/名字、记录缺失、已删除、所属账号不符、记录名字与请求不符、等级索引/记录缺失、等级读取失败、等级记录名字不符和等级达到上限均拒绝；成功读取的真实 0 级仍按原有规则处理。保留原有严格小于 DeleteMinLevel 才能删除的条件，修正 SettingsModel 的反向注释，不改变本机配置。

删除使用新记录副本，保留 Id、姓名、账号、Selected 和 Header；两个 Deleted 标记同时设置，避免存储返回共享对象时在失败前暴露删除。只有 Update 返回 true 才发 SM523，其他分支发 SM524。读取/更新抛异常也发失败回执，日志只记录固定说明，不打印账号、消息体或存储错误文本。MySQL UPDATE 必须实际命中一行，成功后 Header 与 Deleted 一致；GetQryChar 清除旧输出，没有行即返回 false。

删除仍是 characters_indexes.IsDeleted=1 的软删除，不物理清空 characters 或背包。重新载入记录索引时已删除角色不进入账号名单，而 characters 姓名仍存在。没有新增旧名释放时间、恢复角色、批量删除或绕过等级限制。
