# 地图加色前景的双重绘制与偏移 — 2026-10-02

地图前景高位混合标记之前被当成一张普通加色 sprite 绘制，且只有 Objects 帧 2723–2732 会套用偏移。对照参考客户端发现两处差异：`PlayScn.pas` 第一遍会把 48×32 的前景帧按普通图层绘制，第二遍仍会把所有高位混合帧通过 `GetObjsEx` 以加色方式再画一次；偏移由各帧自身的 `nPx/nPy` 决定。第二遍坐标是 `cellX + offsetX - 2`、`cellY + offsetY - 68`，不是只对某个连续帧号区间加偏移。

`apps/web/src/map-view.ts` 现在为高位帧建立加色副本，并在动画周期包含 48×32 帧时才建立普通底图副本。每一帧分别应用其纹理、偏移与普通底图可见性；大尺寸帧不会多分配隐藏副本。普通底图留在原前景绘制层，加色副本仍参加深度排序。

全量扫描572张地图的12字节单元记录，找到2,326条高位混合前景引用，分布在253张地图。与旧绘制坐标对比，1,559条引用的加色副本位置不同（其中1,091条Y坐标不同）；17条引用属于48×32帧，集中在 map 63 的 Objects 帧2749–2756，需要普通底图加加色副本。

地图来源回归16组、地图加载/门组/碰撞回归19组，TypeScript `--noEmit` 与代码产物 Vite 构建（762模块）通过。测试直接实例化生产 Pixi `createMapView`，覆盖48×32两份绘制、100×100偏移、逐帧位置与无需隐藏副本。详细输入和SHA保存在 `.runtime/reports/map-additive-composition-2026-10-02.json`。

这修复的是地图合成逻辑，不代表剩余资源或画面已闭合：全图仍有23张地图的91条背景引用没有可用源图。当前没有原客户端与浏览器同场景截图、GPU逐帧差分，因此 ART-007 仍为 `partial`；下一步应继续查补图来源并做原端/浏览器同帧对照。
