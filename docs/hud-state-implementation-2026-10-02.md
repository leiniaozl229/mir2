# 第十二批：血球、条形资源、饱食与昼夜状态

本批实现生产 HUD 状态绘制和增量同步，扩充可操作的校准样例，并更新已授权本机 18801 测试网关。完整 UI、玩法和美术复刻继续按 195 项总台账追踪。本批不升级同版原端或浏览器 verified。

## 绘制与资源依据

`Client/FState.pas` 的 `DBottomDirectPaint` 第 3608–3637 行：职业 0 且等级低于 28 使用 Prguse#5 空球和 #6 血量填充，右边截去两列；其他角色用 #4，HP 源矩形右界为 `width/2-1`，MP 左界为 `width/2+1`、右界为 `width-1`。据当前国服帧尺寸，整球使用 `(38,90,94,92)`，分球 HP 为 `(40,91,45,90)`，MP 为 `(87,91,44,90)`，均相对主底板。MP 图片左移 47 像素，整球图像保持原始 96×92。两个最大值都必须大于零才绘制血蓝。

第 3646–3676 行用同一个 #7 纹理源矩形前缀绘制经验与负重，800×600 绝对位置分别为 `(666,527)`、`(666,560)`。当前底板 y=349，对应局部 y=178、211。此前经验底图整条直接挂在 track 上，零经验仍露出完整纹理；负重使用纯色填充。本批让空轨道显示主底板，只在 fill 中裁切原纹理，宽度变化不缩放纹理。

裁切按 Delphi `Round` 的半像素取最近偶数规则处理；血球保留底部原像素，条形资源保留左侧原像素。正常值和半像素样例已测试。Web 对越界资源值限制到有效区间；该保护处理不是异常原端像素行为证明。零上限按参考条件抑制相应绘制。国服 HUD 隐藏参考绘制中未出现的血/蓝/经验数字覆盖层，保留权威值并以 hover title 提供读值；这个读值方式属于 Web 可访问性适配。

第 3595–3604 行为昼夜图标：phase 0/1/2/3 对应 #15/#12/#13/#14，x=748，y 为 `79+DBottom.Top`。当前网页以主底板作为相对原点；这个父控件对齐仍须同版原端复核。第 3681–3686 行将状态 1–4 映射 #16–#19，绝对 `(754,553)`。0 或未知状态不绘制饱食图标。帧原始 offset(+7,-44) 保留在清单，当前显式绘制坐标没有再次叠加它。

`Client/ClMain.pas` 的 SM_DAYCHANGING 分支使用 Param 作为 phase、Tag 作为 DarkLevel；初始 phase 为 3。网关新增消息 46 的 typed 投影 `{type:"daylight",phase,darkLevel}`，保留原始字段；角色灯光消息 654 未被误当全局昼夜。网页只绘制已知 phase，不使用本机时钟推测游戏时间。地图黑暗度保留在协议和组件状态中，地图暗层/雾与角色灯光尚未实现。

Prguse#1/#4–7/#12–19 共 13 个选定 PNG 由原始国服 WIL/WIX 导出。本批没有改动 PNG 或源库。原始 WIL/WIX 当前哈希匹配导出清单；13 个 PNG 在源文件、当前 HTTP 和 dist 中逐字节相同。参考源、清单和像素锁见 `hud-state-v12-baseline.json`、`hud-state-v12-runtime.json`。像素来源证明不能替代合成画面与原端动态比较。

## 权威值与玩法同步

原 weights 分支只更新人物窗口，本批同时更新 HUD，捡取/丢弃后负重条无需等待下一次血蓝事件。SM_STRUCK 投影出的玩家 health 同时更新人物窗口和血球；怪物 health 只更新对应实体。HP/MP、升级、经验、负重、饱食和昼夜均从服务器投影驱动，素材异步加载完成后绘制已收到的最新状态。退出清空和换角继续使用现有会话/地图代次隔离。

饱食文字的旧含义也被纠正。当前原服 `GetMyStatus()` 返回 `HungerStatus/1000`，最高为 4；`EatItems` 的 StdMode=1 增加食物储量，最大为 5000，跨档时才发送 RM_MYSTATUS。因此状态高代表储量更高，原来的 3/4→“很饿/饥荒”和红色告警方向错误。当前显示中性的“饱食等级 1–4”，不会因高档储量制造饥荒告警。服务端减少储量及饥饿影响由既有 HungerSystem/HungerDecHP 配置控制，本批没有在浏览器补本地倒计时或改变原服配置。

新增实际原服类回归 6/6：状态档位/上界、进食跨 0→1 与 3→4、同档不重复刷新、5000 上界、禁药地图拒绝。执行真实 GetMyStatus、私有 EatItems 食物分支和实际消息队列；无关能力重算与网络是 boundary fakes。它没有验证完整物品使用 ACK、背包消耗、定时饥饿、角色数据库或持久保存。
