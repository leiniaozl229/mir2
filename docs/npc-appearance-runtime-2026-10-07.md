# 原客户端 NPC 外观取帧与运行核对

本轮修正的是外观号被直接当成图片帧号的问题。真实登录协议发送 `feature=327730`，低字节为 NPC 种类50，高16位为外观号5。旧 `OnlineActor` 直接加载 `NPC00#5`，该图只有4×1像素，不能显示原客户端截图中的人物。

同一角色在比奇338:264的原端截图75中，比奇药师、比奇铁匠、首领传送员分别匹配原库的#320、#301、#313，平均通道误差8.40、8.02、10.53，格锚点位移均为0。匹配遍历了原导出库中的有效人物候选，包含透明遮罩、图片原始偏移、PNG哈希和截图SHA。JPEG误差与单帧匹配不能证明完整动画、字体或鼠标热区通过。

`content/classic-176/npc-visuals.json` 独立固定 NPC00 原始 WIL/WIX 哈希、2790帧边界、外观段偏移与三方向取帧规则。外观5读取#300–303、#310–313或#320–323。其他外观段使用 `Actor.pas:GetNpcOffset` 的参考实现，仍需逐种同版运行核验。参考快照中的 `MA50` 名称没有完整声明，本轮四帧、步进10、200ms使用MA41参考定义；截图可支持帧身份，原端实际动画间隔仍待连续取证，未标为运行确认。

`npc-visuals.ts` 与 `OnlineActor` 共用生产/场景校准渲染路径。取帧前校验完整库身份与四个帧条目；缺段、错版本或坏PNG会保留未解析状态，不落到#5或外观0。资源错误会在下一次真实更新时重试。异步方向更新或角色移除仍由原有代次隔离；已显示的人物在相同外观更新时不再重画金色占位圆。
